# 真机验证清单

F1 解析规则、F2 身份码/二维码、F3 剪贴板导入、F4 通知来源、F6 首页检索这五笔都已提交，
但它们的证据最高只到**单测 + SQL 层**：解析棘轮、视觉棘轮、两百个 JVM 用例都管不到
「柜机那颗摄像头拍不拍得清」「迁移在真库上跑没跑」「关掉之后是不是真的不入库」这类事。

这一页就是把那次设备会话要按的顺序写下来。**跑的时候只报编号 + 一句话现象**，
失败的那条我会先在 HEAD 上复现归因，不凭现象猜。

## 已跑过的部分（2026-10-14，vivo V2364A / Android 15，`adb install -r` 覆盖装）

**A 组通过**——这是这张单子里唯一「坏了就毁数据」的一类，所以先说它靠什么算过：
装新版之前那台机器上的库停在 `user_version = 3`（真的旧库，不是造的），
覆盖安装并启动后逐列比对拉下来的两份文件：`user_version` 3 → 6、
`parse_rule` / `identity_code` / `notify_app` 三张表出现、**没有任何表丢失**、
六张旧表的行数与整表内容 sha256 **逐列未变**（2 件包裹、3 条未识别、meta 全在），
屏上首页仍是那 1 张待取卡、引导没有重来。

**D 组的核心那条通过**，而且是它最可能被卡住的地方：`readText()` 在 Android 15 上读得到。
现场长按复制 `6-2-3391` → 进手动导入：原文框**是空的**（裸一串码没有取件语境，自动那档判 NOT_PICKUP，
也没出声）→ 点「粘贴剪贴板」：同一段文本**填进去了**。
这两步一起才是这一笔的主张：两条路的松紧不同，在设备上成立。

**G 组通过**（含三句空结果的话）：搜 `3391` 命中；搜 `33919999` 出「没有和…对得上的待取件」；
搜已取走那件的 `2277` 出「有 1 件已取走的和它对得上」；空着字只选「急件」出「这一档里没有待取的件」
（**没有**冒出一句已取过——那是判据要求的行为）；筛选生效时引导卡让位、「手动导入」那行不让位；
清回「全部」后一切复原。另外顺手验到「今天到」把一条 10-12 到的件正确挡掉。
⚠️ G7 的另一半**没验到**：未识别入口行这次压根没出现——库里那 3 条都是外卖域、角标为 0 是预期行为，
所以「筛选时它也不让位」这一条要等有一条真的没认出来的快递短信时再看。

**没跑的**：B（规则屏要手打中文，adb 输不进）、C（身份码与摄像头，见下）、E（通知来源要能推真通知）、
G2（软键盘遮挡——这台机器上 `input text` 不弹 IME，所以那一格等于没验，别当成过了）。
C1 剩下的那一半仍然只能他做：把手机递给柜机，看那颗摄像头拍不拍得清。

## 0 · 准备

- 优先级：**vivo > 其他真机 > 模拟器**。只有 vivo 能注进真短信和真通知；
  模拟器只能验 A 组（迁移）和 B/C/D 组的纯 UI 部分。
- adb 不在 PATH：`C:\Users\example\AppData\Local\Android\Sdk\platform-tools\adb.exe`
- 覆盖安装**不丢数据**的前提是同签名：`adb install -r app-debug.apk`。
  release ↔ debug 换签名必须卸载，那一卸数据就没了——A 组要的就是「不卸」。
- 读库用 `run-as`（App 能读写自己的库，只有系统短信库被拦）：

```bash
adb shell run-as dev.showcode sqlite3 databases/showcode.db "PRAGMA user_version;"
adb shell run-as dev.showcode sqlite3 databases/showcode.db ".tables"
```

ROM 里没有 `sqlite3` 就把库 `tar` 出来在桌面看。**动手前先把库备份一份**：
`adb exec-out run-as dev.showcode tar -c databases > showcode-backup.tar`

## A · 迁移 v3→v4→v5→v6→v7（优先级最高：唯一「坏了就毁数据」的一类）

这是四笔里唯一一旦错就无法用「再点一下」纠正的东西，所以放在最前面。

- **A1 造一个老库**：装 `59c627e` 那个构建（那时 `VERSION = 4`），走完引导、刷新收进 2~3 件、
  手动导入 1 件、把 1 件标成已取。记下三个数：**待取件数、本月已取、未识别条数**。
- **A2 起点核对**：`user_version` 应为 4；`parse_rule` 存在；`identity_code`、`notify_app` 不存在。
- **A3 升上来**：不卸载，`adb install -r` 现在的 v7 构建，起 App。该看到：
  - `user_version` = 7；三张新表都在；
  - 旧的那几张身份码**照旧在列表里**，徽章仍是「固定」或「会变」——v7 给 `identity_code` 加的
    那一列 `kind` 默认是 CODE，升上来变成「入口」或整张码不见了的，都是那一列写坏了；
  - A1 记的三个数**一个都没变**（尤其「本月已取」不许被吹大——那是 v3 那笔修过的老 bug）；
  - 引导**没有**重来，首页仍是原来的件。
- **A4 幂等**：再杀再起一次，不该有任何重复建表或数据变化。
- **A5 全新库**：卸载重装（这是唯一允许丢数据的一次），三张表齐全、列表为空、引导走完。
- **这一组里已经不用在设备上重复跑的**：`tools/migration-check.py`（第四条棘轮，CI 里跑，纯标准库）。
  它从 **v1 形状起手**，按源码里的顺序把每一档迁移连跑到底，然后验「旧表行数不变 +
  `parcel` 整表逐列不变（`picked` / `picked_at` / `raw`）」、把 DAO 里每一条 `SELECT`
  逐字打在这张升过级的库上，以及**比较「一路升级出来的库」和「全新安装的库」每张表的列是否一模一样**
  （v7 之后不再逐字比对两份 DDL 文本：`identity_code.kind` 新装时写在 CREATE、升级时靠一条 ALTER 补，
  两份文本本来就该不同；而列集合比对照样抓得住「建表加了列忘了配 ALTER」那一类）。
  外加 `notify_app` 那条 upsert 的两半（不许冲掉 `disabled`、第一次到达必须计 1）。
  这一类错里最贵的那个它已经抓过一次：`seen_count` 第一次到达记成 2（修在 `aee1f9e`）。
  ⚠️ 并且它被**故意做坏过六次**——抬 VERSION 不加分档、加表不写迁移、DAO 写错列名、
  把插入值改回 1、只改一份建表语句的默认值、**拿掉 v7 那条 ADD COLUMN**——每一次都红，
  还原后重跑才绿。最后那次报的是「升级库少一列 `kind`」加两条 DAO 读打不通，
  证明新的列集合比对不是摆设。
  一个从来不会红的检查等于没有检查，所以这句要写在单子里而不是只写在 commit 里。
- **仍然只有设备能答的**：`onUpgrade` 真的被调用、真的作用在你那个旧文件上。
  这一条在这台机器上没有任何替代办法，A1~A4 跑的就是它。
- 如果 A3 的三个数对不上：**立刻停手别继续点**，先把备份留着再排查——
  十有八九是 `onUpgrade` 里 `oldVersion < N` 的分档写错，或者 `onCreate` 与迁移两份 DDL 漂移了。

## B · F1 解析规则（`59c627e`）

- **B1 收容页那一行四个动作**（手动提取 / 写条规则 / 忽略 / 不再显示此类）在窄屏上是否完整可见，
  `FlowRow` 换行有没有把一个标签截断。
- **B2 就地写规则**：从没认出来的那条点进去，原文应已经带着；抄码 → 生成 → 预览那句该是
  「会认出来：码 ……」。
- **B3 保存之后当场救回**：900ms 回列表，列表里多一条规则；**同时**收容页里那条要消失
  （标成已处理，不是删行）。这是「重判库里挂着的未识别」唯一的现场证据。
- **B4 只做加法**：拿一条标准菜鸟短信（内置本来就认得）配一条故意写歪的规则存进去，
  刷新收件箱——已经认对的件一件都不许变。
- **B5 关掉一条规则**：已有的件**不**回退（规则只负责认码，不负责撤销历史）。
- **B6 删除**：要两次点击，第一次只把文字变成「再点一次确认删除」。

## C · F2 身份码 + 二维码（`ad33958`）

- **C0 先扫这两张 PNG，别急着扫手机**：`docs/qr-selfcheck-8-9-0765.png`（第 1 版，21 模块）和
  `docs/qr-selfcheck-long-url.png`（第 3 版，29 模块）。它们是**用仓库里那份 vendored 生成器**
  直接出的图，走的同一套约定（ECC-M、版本上限 15、四周 4 模块静区、深色模块=墨色）。
  所以这一条是**分诊**用的：
  - PNG 扫得出、手机屏扫不出 → 问题在 `QrMatrixCanvas` 那层（0.5px 那条边、方图尺寸、density 换算），
    生成器和约定可以排除。
  - PNG 也扫不出 → 问题在生成器或这套约定本身，改渲染是没用的。
  没有这一条，C1 失败时这两件事在柜机前**分不开**，只能来回猜。
  两张图的像素已经用另一个实现（Pillow 采样）逐格比回矩阵：模块颜色、静区全白、
  三个定位角在位而右下没有，全对。
- **C1 这是整笔最硬的一条**：把手机递给柜机/自助机，或用任意扫码 App 扫屏幕上那张码，
  扫出来的字符串必须和你存进去的值**一字不差**。
  这一条现在已经**拆成两半**，剩下一半才是设备的：
  - 已进 CI（`QrRasterTest`）：在 JVM 里把光栅写成一张真 PNG、再读回来逐格比对矩阵——
    上下颠倒、深浅反色、静区漏画、映射差一格这四类错从此在合并前就会红。
    画布的尺寸取的是同一个 `modulePx`，所以「测试证明的那套映射」和「屏上真正画出去的那套」是一份算术。
    转置那一类还被专门验过一次的样本不对称性兜住（样本矩阵若对称，这条测试等于没跑，测试自己会报）。
  - 仍然只能设备验：Compose 把矩形画上那块屏之后的事——0.5px 描边在整数对齐下够不够、
    density 换算、屏的对比度与反光。所以 C1 剩下的主张是「**那颗摄像头拍得清**」，
    不再是「我们画的到底是不是那张码」。
- **C2 亮度与常亮**：那一屏该拉满并保持常亮；退出后恢复系统亮度。
- **C3 远一点、斜一点再扫**：验的是每个模块多描那 0.5px 边——整除对齐时那条缝在屏上看不见，
  在扫码器眼里是一根切断码图的白线。
- **C4 太长的值**：粘一条 300 字节的 URL 进去，保存时该被拒并说清「编不进 15 版」，而不是崩或者画一张扫不出的巨码。
- **C5 官方 App 那颗按钮**：选一个**装着的** App → 应跳到它；选一个**没装的** → 应明说没装。
  如果「明明装了却说没装」，是 manifest 的 `<queries>` 包可见性漏了（targetSdk 30+ 这是可见性问题，不是权限问题，一声不响）。
- **C6 标了「会变」的那张**：出示屏必须提醒你别硬试。这条测的是产品诚实度，不是功能。
- **C7 幽灵码**：开着出示屏，在另一个地方把那张码删掉 → 回去应退回列表，
  不许继续出示一张已经不存在的码。
- **C8 入口那一类**（v7 之后新增）：存一个「去取件」的入口（不填任何码），然后看三处：
  列表里那一行**不该有一格空着的码值**、徽章该是「入口」而不是「固定」、
  点进去该是一句「用它现取」加大按钮，**不该出现「画不出能扫的码」那句报错**。
  这一类最可能的错法就是把「本来没有码」演成「码坏了」——那会让人以为是自己抄错了。

## D · F3 剪贴板导入（`3caa42c` + `3306478`）

- **D1 主路径**：在短信 App 长按复制一条**取件短信** → 打开手动导入 → 原文框该已经填好，
  而且屏上**不该有一句解释**（自动那一档按设计不许出声）。
- **D2 不该填的**：复制一条验证码或营销短信 → 进那一屏不许填，也不许说话。
- **D3 一整页聊天**（>500 字）：不该自动填；点「粘贴剪贴板」那一下 → 该照填。
- **D4 不许顶掉你打的字**：在原文框手打半句 → 退出 → 再进（剪贴板里留着取件短信）→ 你那半句必须还在。
- **D5 已经导过一次的那条**再复制一次 → 不该再自动填（库里见过的正文）。
- **D6 剪贴板是空的**时点粘贴 → 该给那句「先去长按那条短信复制，再回来点这一下」。
- **D7 别叠两句**：Android 13+ 系统自己会弹「已粘贴」的提示，确认我们没在它下面再补一条。
- ⚠️ 如果 D1 从来没填上过：那是**焦点限制**（Android 10+ 要 App 在前台有焦点才读得到剪贴板），
  结论不是「判据坏了」，而是自动那一档要砍掉、只留 D3 那颗显式按钮。

## E · F4 通知来源（`d282272` + `f3a4a7c`）

- **E1 列表有没有东西**：给完通知使用权，让两三个 App 各推一条，那一屏该列出它们，
  显示名正确（名字来自 PackageManager，不是我们写的）。
- **E2 关掉真的管用**：关掉一个 App → 它再推一条 → 首页**不增件**、收容页也不增。
- **E3 反悔没有代价**：重新打开应一次点击走完，不该有二次确认。
- **E4 关掉「转发过代取件」的那个**（典型是微信）：第一次点击只把警告放大，第二次才真关。
- **E5 空态那句是诊断**：如果你确定给过权限却还是「还没见过任何通知」，
  说明监听被 ROM 静默收回了——去首页那条体检看权限状态。
- **E6 确认文案没骗人**：关掉期间推来的那条，重新打开后**确实不回**。这是承诺不是 bug，
  验它是为了确认那句「永久收不回」写在屏上时是真的。
- **E7 不许串**：两个 App 的「第二次点击确认」态不能互相影响（确认态是按包名存的）。
- **E8 那行数字得是真的**：某个 App 只推过一条，那一行必须写「推过 1 条」，第二次推来是 2 条。
  这条是迁移探针在真 SQLite 上抓出来、已在 `aee1f9e` 修掉的算术错（插入那行给了 1，
  紧跟的 UPDATE 又无条件 +1，第一次到达就计成两条）。`data/` 一层没有测试框架，
  所以**屏上是它唯一的验收处**。同一条顺手验另一半：关着的时候它继续推，
  那一行只该涨次数、`disabled` 不许被冲开（那条 SQL 刻意不写整行）。

## G · 首页检索（`e00f221` 判据 + 本屏）

判据有 14 个单测钉着，**这一屏本身零覆盖**——Compose 的渲染要设备，JVM 够不着。

- **G1 那颗搜索按钮只在有待取件时出现**：把件全标成已取 → 按钮该消失，而不是点开一个空框。
- **G2 打字时不许被键盘顶走**：搜索框挂在列表外面，软键盘弹起来时它必须还在可视区。
  这条是「会随列表滚走的控件等于没有」那一族的，验不过就要改落点而不是改文案。
- **G3 只过滤不重排**：搜一个命中多个点的词，卡片顺序应当仍然是「最急的那个点在最上」，
  而不是变成按时间或按命中数排的列表。
- **G4 分隔符**：存一条 `5-2-7712` 的件，搜 `527712` 应当命中。
- **G5 「急件」那一档含红卡**：选它之后，临期**和**过期风险的都该在；
  如果只有黄的没有红的，就是判据那格「不只筛 DUE_SOON」被 UI 改回去了。
- **G6 已取那句只在打了字之后出现**：空着输入框只选一个时间窗，得到的是
  「这一档里没有待取的件」，不该冒出一句「有 N 件你已经取过了」。
- **G7 两件不许跟着筛选消失**：未识别那条入口行、列表末尾的「手动导入」。
  前者是失败显性化的红线，后者的契约是常驻——搜不到的那一刻正是它最值钱的时候。
- **G8 清空与收起**：清掉字之后列表当场回到全量；收起搜索之后不该留下任何过滤状态。

## H · F5 下拉栏磁贴

**已经在设备上验过的**（vivo / Android 15，`adb install -r` 之后）：系统能发现这颗磁贴——
`cmd package query-services` 列出 `dev.showcode.ui.tile.PickupTileService`，
`enabled=true exported=true`，label / icon / description 三个资源都解析到了。
也就是说 manifest 接线、权限声明、图标这三件事不再是「只过编译」。

**没验到的**：把磁贴拖进面板之后的全部行为。vivo 的 QS 编辑器入口 adb 找不到
（面板里只有「展开 / 收起」，没有可点的「编辑」节点），所以这一格起就是你的手指：

- **H1** 进 QS 编辑，列表里该出现「取件码」，说明文字是那句「点一下立刻重读收件箱…」。
- **H2 没给通知监听时**：标题该是「取件码 · 未开启」、副标题「点我去开通知监听」；
  点一下要把系统那块监听设置页摊开。**不许出现任何件数**——那是判据在挡一块骗人的平安牌，
  如果它显示了「没有待取件」，就是 `tileReadout` 那条归零被绕过了，算 bug 不算小事。
- **H3 开了监听之后**：标题回到「取件码」，副标题报「N 件待取 · M 件急」；
  点一下刷新——件数真的变了的话磁贴要**自己重画**（刷新是异步的，
  `invokeOnCompletion` 之后才 render；如果点了没反应、要重新拉一次面板才更新，就是这一格）。
- **H4 一件都没有时**：副标题「没有待取件」，磁贴**不许变灰**。灰掉读起来像坏了。
- **H5 「急」那一档含过期风险**：造一条只剩 10 分钟关门的件，副标题的 M 要把它算进去。
- **H6 Android 9 以下**（拿别的机器顺手看一眼）：没有副标题这一行，标题必须自己把状态说完。
- **H7 刻意没做的**：社区那个「重写 `enabled_notification_listeners` 逼系统重绑」的自救技巧
  没有实现——它要 `WRITE_SECURE_SETTINGS`，普通安装只会抛 SecurityException。
  所以监听被 ROM 杀掉时，磁贴不会假装修好了它；那条红仍然由首页体检条负责。

## I · ⑦-a 每次进待取页自动刷（胶囊 → 顶栏那行小字）

底部那颗「立即刷新」胶囊删了，位置让给即将来的底栏；它那句「上次同步到什么时候」搬进顶栏标题下面。

- **I1 真的会自己刷**：收一条取件通知（或让家里人发一条短信）→ 回到待取页，**什么都不用点**，
  那行小字该先变「正在同步…」再变「新增 1 件」，随后回到「更新于 刚刚」。
  如果它一直停在旧时间，就是 `LaunchedEffect(route)` 那条没触发（比如首页不是每次真的被「进入」）。
- **I2 快速来回不许排第二遍**：待取页 → 某个点的现场 → 返回 → 再进 → 再返回，连做几次。
  小字不该长时间挂在「正在同步…」——`refreshNow` 在读的过程中直接不排第二个，
  两次查询用的是同一个游标，第二次本来什么都读不到。
- **I3 短信权限掉了不报警**（2026-11-04 方向调整）：把短信权限在系统设置里关掉 → 回待取页 →
  首页**不该出现任何短信相关的红条/警示条**（`HealthReport` 不再产生 `SMS_DENIED`）。
  顶栏那行会停在最后一次成功的时刻慢慢变陈——`backfillSms` 没权限时直接返回，不置失败位。
  设置页的「短信导入（可选）」变成中性灰的「未开启」+「开启（可选）」，
  不进首页横幅、不用 `UrgencyDueSoon`。通知监听缺失仍然照旧用体检条提示。
  真正的「同步失败」那一档，只有**有权限却查询抛错**时才出现，模拟器上造不出来。
- **I3c 引导主路径是绑定账号**：首次打开的 WELCOME 主按钮是「绑定平台账号」，
  点进去落到 ACCOUNTS 步；短信入口只作为「也可以用短信导入（可选）」的文字链接。
  短信步的主按钮是「不用短信，继续」，只有主动点「允许读取短信（可选）」才弹系统权限框，
  允许或拒绝都继续走下一步。
- **I3b 只给通知权限的人**：进首页这一次自动刷是**空转**（通知本来就是推的，没有可回读的收件箱）。
  他看到的那行小字只会跟着通知到达而不动——这不是坏了，但值得确认那句「更新于 X」不会让人
  以为 App 在漏刷。
- **I4 手动入口现在只剩一处**：红条里那句「重试」。红条没出现时你**没有任何**手动刷新按钮，
  这是这一笔的设计而不是遗漏（自动刷 + 权限失效时那条红就是它的兜底）。
  站在这一屏上觉得「想刷一下却没地方点」是正常的，别把它当 bug 记。
- **I5 那 8 秒不该飘**：「新增 N 件 / 无新件」只露 8 秒。看一眼它是不是大致 8 秒——
  页面那个时钟是 30 秒一跳的（给倒计时用的），这一句没跟着它走，所以它不该出现
  「时快时慢、或者整整挂半分钟」。

## J · ⑦-b 底栏三颗键（待取件 / 身份码 / 设置）

底栏浮在列表上方，落点就是原来那颗刷新胶囊的位置。

- **J1 三颗键都在，且只有一颗是选中态**：进 App 该停在「待取件」；点「身份码」到列表、点「设置」到设置。
  选中的那颗是强调色加一层淡底，未选中是灰的——**切换时标签的字宽不该变**（变了整排键会左右晃）。
- **J2 滚到底不被压住**：首页滚到最后一张卡、身份码滚到那颗「＋ 存一张」、设置滚到最末一格，
  三处都要**完整露出来**。这一条是那个底部净空唯一能用眼睛验的方式。
- **J3 子屏不许有底栏**：点某个取件点进现场模式之后底栏该消失——那一屏只该有那张码和那颗按钮，
  一排键摆在那儿是挡道的；按返回回来后它该重新出现。
- **J4 设置只剩一个入口**：首页右上角现在只有搜索那颗键。如果你在两个地方都能进设置，那是回退。
- **J5 三块标题对齐在同一列**：「设置」「身份码」的标题要和首页「待取件」左边缘对齐。
  错开一截会被读成「这两屏不是平级的」——那正是底栏要消灭的东西。
- **J6 返回键的语义**：在「身份码」那一格按系统返回 → 回待取页，**不是**退到桌面；
  在待取页再按一次才退。身份码出示屏按返回 → 回列表。
- **J7 底栏不许和手势条重叠**：它自己吃系统栏内边距。如果它贴到了屏幕最底边、被手势条压住一半，
  就是那层 inset 没生效（手势条机型和三大金刚键机型要分别看一眼）。
- **J8 字号开到最大**：系统字体放大到最大档，三个标签（待取件 / 身份码 / 设置）不许把底栏撑出屏宽、
  也不许被裁掉一半。底栏的宽度是按默认字号排的，这一条只能在你机器上看。

## K · ⑦-c 预置直达（身份码那一格的「去取」）

- **K1 装了才有，没装就整格不出现**：装了淘宝或拼多多的机器上，身份码那一格顶部该有一到两行「去取」；
  两家都没装时那一格该**整个消失**——留一个空壳比没有更坏，而列出一家点不动的更坏。
  如果它把没装的也列出来了，是筛法被绕过（判据在 `DeepLinkLadder.entriesFor`）。
- **K2 点一下到底落到哪一屏** —— ✅ **2026-10-15 已在模拟器上核实**（装到拼多多之后当场跑的）：
  `pinduoduo://com.xunmeng.pinduoduo/mdkd/package` 落在它的**「取快递」页**（`NewPageActivity`，
  屏上标题就是「取快递」），不是首页。这正是巡检要去的那一页——上面写着「今日有 N 个快递待取」。
  顺带发现：拼多多的**「身份码」是底部三个 tab 之一**（取快递 / 身份码 / 个人中心），和取快递同级，
  所以从我们那一格到身份码是**两步**（点预置 → 点它的 tab）。
  **直达身份码那条 path 拿不到**：它 manifest 里声明了 174 个 scheme 但 **0 条 Path 模式**——
  路径全在它内部路由器里，`pm dump` 枚举不出来；底部 tab 的节点名也是混淆的
  （`content-desc=fJRFPEceAsHcUAcEAfEA`），所以只能靠猜候选 + 逐条验落点，不值得为省那一步去做。
  仍要你自己确认的只有一件事：**装了淘宝的机器上那条 tbopen 链落哪**（这里没有淘宝）。
- **K3 「点了没反应」必须说话**：小米/iQOO 那类拦截下按下去，那句红字该出现在**刚按的那一行下面**
  （常驻的一行，不是 toast），而且说的是「去开链式启动」不是「没装」。
- **K4 入口那一类不再要求填名字**：存一张 → 选「一个去取件的入口」→ 选那家 App → 存。
  列表里那一行的标题会自动是那家 App 的显示名。**这是有代价的**：显示名由 PackageManager 给，
  同一款在不同 ROM/语言下可能是「淘宝」也可能是「手机淘宝」——看到了别当 bug，
  但如果你机器上那个名字短到分不清是哪家，那就要回来改。
- **K5 存码那一类不受影响**：名称、码值、粘贴、二维码能不能编、「会不会变」那几格都照旧在，
  且名称仍是必填（那是现场念给人看的那一行）。
- **K6 两处列的必须是同几家**：这一格和存码屏那排快捷项共用同一份筛法。
  一个列两家、另一个列一家，就是有人又把判据抄了第二遍。

## L · ⑧ 已取件不进首页 + 通知来源那道门

- **L1 点已取即时消失**：同一取件点有 2 件，取走 1 件 → 首页那张卡的件数**当场**从 2 变 1；
  取走最后 1 件 → 整张卡消失，**不留「0 件」残卡**，也不出现任何「最近已取」栏。
- **L2 再同步不复活**：对已取件再同步（账号渠道同样）→ 不新增、不回填、`picked` 仍为 1；
  无码件（`code=""`、`tracking_no` 有值）同样不复活。记录留在库里，但任何待取列表都不展示。
  全部取完时首页空态应是「都取完了 🎉 本月共取 N 件」。
- **L3 门（关键的一条）**：同一个 App 推两条通知，一条是「余额变动」这种与取件无关的内容、
  一条带取件码。前者**不该**出现在「通知来源」那张表上，后者该出现。
  我在 MuMu 上用 `cmd notification post` 从同一个包名各发过一条，验的就是这个对照。
- **L4 那行数字说的是它数到的东西**：那一行写「与取件有关 N 条」，不是「推过 N 条」——
  被门挡掉的那几条根本没进这张表，写成「推过」就是一个永远对不上的数。
- **L5 门不许误伤 F4 那条不变式**：把一个来源关掉，它**再推一条带码的通知** → 那一行的到达数该继续涨、
  「上次见到」该更新。这道门有一条例外正是为此留着（已经在表里的来源一律继续记）；
  如果关掉之后那一行冻结在关闭前，例外被写坏了。
- **L6 收录本身没被门挡坏**：带码那条通知要真的变成一个待取件；
  而「没认出来的取件短信」那个数**不该**因为银行通知而涨。

## M · ⑨ 巡检提醒（治「有些件平台根本不推」）

它存在的理由：**漏件发生在你不打开卡皮巴拉快递助手的时候**。所以任何只在 App 内的提示都治不了漏，这一组验的是那条主动通知。

- **M1 它什么时候该响**：早上 9 点（不精确，系统可挪几分钟）。第一次响之前，你**必须手动录过至少一条件**——
  那是「有平台不推给你」的唯一可靠证据。从没录过件的人收到这条提醒，就是判据被绕过了。
- **M2 点开要直接落在那一格**：通知点开来应当直接出现在「身份码」那一屏（预置的「去取」在那儿）。
  如果它只是打开 App 让你自己找，这条提醒等于白发的。
- **M3 拒了权限要说真话**：不给通知权限时，设置那一格下面必须红着一行「没给的话这条提醒不会响」，
  而**开关不许被偷偷关掉**。偷偷回滚一个用户刚打开的开关，比不告诉他更坏。
- **M4 重启之后还在**：闹钟不跨重启。重启手机（或 `am broadcast` 一次 BOOT_COMPLETED）之后第二天仍该响。
  这一条靠的是组件那个已有的 boot receiver 顺手重排——所以组件那格被改坏时这里会连带坏。
- **M5 一天只响一次**：同一天内反复触发（手动广播 + 到点）只该看到一条。按自然日不按 24 小时滚动，
  所以半夜不该补响一次。
- **M6 关掉就彻底安静**：设置里关掉之后，任何路径都不该再发（包括重启、包括手动触发）。

## N · ⑩ 现场三件套（常亮 / 静默 / 收工卡）

这一组只有真机能答：常亮是 Window flag，静默是时间与触摸，收工卡要两个真实取件点。

- **N1 站着不动不熄屏**：进现场模式后放下手机等 60 秒（系统息屏设成 30 秒更明显），屏幕不许灭；
  从平铺总览、身份码出示进去也一样。退出那一屏之后系统息屏要**恢复**——flag 泄漏会让整个 App 常亮。
- **N2 8 秒后只留三样**：顶栏、分组、位置行、「已取」、复制提示全部退场；
  码、格口、倒计时仍在原位，**码的大小和位置不许跳**（控件只改 alpha、不撤布局）。
- **N3 第一下只唤醒**：静默后点一下「已取」原来的位置——只该恢复控件，不该把件标成已取；
  在码上横滑也只该唤醒，不该翻页。第二下才恢复正常操作。
- **N4 计时会被动作重置**：碰一下之后 8 秒内继续操作，不该再次静默；翻页、切组、撤销条出现都重新计时。
- **N5 收工卡说对下一站**：在 A 点取完最后一件 → 出现「下一站 · B」，件数与剩余时间要和首页 B 卡片一致；
  若 B 比 C 急，下一站必须是 B（沿用首页排序，不另立一套）。
- **N6 跳过去是干净的**：点「去这里」→ 落在 B 的现场模式，分组是「我的」、页码是第 1 件、码是 B 的码。
  这一条最容易坏在「route 没变、屏没重建」——B 只有代取件时会看到一个空的现场模式。
- **N7 撤销仍然有效**：收工卡出现后 3 秒内点撤销 → 码回来、收工卡消失；超过 3 秒撤销条消失。
- **N8 该不静默的地方不静默**：开 TalkBack 进现场模式，等 15 秒控件不许消失；演示模式同样不许静默，
  且演示里不出现「去这里」（跳点会让刚取掉的演示件复活）。

## O · ⑪ 划词入口（`ACTION_PROCESS_TEXT`）

只有真机能答：菜单是系统画的，冷/热启动的差别也只在设备上才看得见。判据里唯一能单测的是
「只拒空」，那 5 条已经在 `TextIntakeTest` 里了，这一组验的是**接线**。

- **O1 菜单里真的有「卡皮巴拉快递助手」**：在菜鸟 App 长按单号 → 系统文本选择菜单出现「卡皮巴拉快递助手」。
  不出现先查两点：选中的是不是可选文本（自绘/WebView 里的字选不中），以及无障碍服务有没有把菜单接管掉。
- **O2 冷启动带着原文**：先杀掉进程，再从菜单点进来 → 手动导入页的原文框里就是刚选的那一段；
  首尾空白被剪掉，中间的换行、空格一个字不动。
- **O3 热启动不新建任务**：App 已经开着（停在现场模式）→ 从菜单点进来 → 落手动导入；
  按返回回首页，再次按返回退出。不许出现两个「卡皮巴拉快递助手」任务叠在最近任务里。
- **O4 空选中什么都不发生**：选中纯空白再点「卡皮巴拉快递助手」→ 不许跳进一个空的手动导入页，停在原处。
- **O5 不自动落库**：进来只是预填。没按「保存」之前，返回首页看件数——**一件都不许多**。
- **O6 拼多多选不中不算 bug**：拼多多物流页若是自绘/WebView，长按可能根本不弹文本菜单。
  记在这里是为了下次不再把它当缺陷查一遍；那条路只能靠「复制单号 → 剪贴板导入」或者分享入口。

## F · 回归：这几笔都不该动的东西

四笔都是加法，所以这些老契约如果坏了，就是新代码越了界。

- **F1 现场模式**：12 位的码不撑破屏；短信没有柜号时那一整块**消失**且码变得更大，不是留一个空位。
- **F2 三态紧急度**：安全/临期/过期风险只有三种颜色，倒计时逐秒跳、整行不许左右晃。
- **F3 合并**：提示 → 预览两边 → 合并 → 5 秒内撤销 → 详情页拆开，件数一件不丢。
- **F4 桌面组件**：点某一节一步直达那个点的现场模式；单独钉的那个组件只显示它自己那个点。
- **F5 已取的不再被刷新复活**：这是 v3 那笔修掉的 bug，也是**迁移之后最容易复发**的一条——
  取走一件、退回待取页（它现在自己会刷）、确认它不回来。

## H · 平台账号与自动收录（P2–P5）

- **H1 绑定**：设置 → 平台账号 → 拼多多「去登录」，在官方 WebView 里用手机号+短信登录；
  返回列表后显示「已绑定」，密文落库（`bound_account.secret` 不含明文 Cookie）。
- **H2 同步**：点「立即同步」，等 30–60 秒；结果行报新增/更新/跳过数，首页出现账号件。
- **H3 后五位**：拼多多菜鸟驿站件在首页卡里显示 `76416` +「后五位」；
  现场模式码上方显示「出示单号后五位」，码的纯黑/等宽/防溢出不变。
- **H4 已取不复活**：现场点「已取」→ 再同步 → 这件不出现在首页，`picked=1` 不被冲回 0。
- **H5 签收不误标**：只有轨迹明确「本人取件 / 凭码取件」才自动 `picked`；

- **H7 失效/离线**：断网/过期 Cookie 时同步失败但不清库、不显示「今天没有要取的」。
- **H8 升级**：v7 旧库覆盖安装到 v8，`user_version` 7→8，旧包裹行数与内容逐列不变。
- **H9 真机**：模拟器（MuMu Android 15 / WebView 110）能过 H1–H7，不等于真机结论；
  京东/淘宝需各自登录一次才能验 H2。

## I · 淘宝 / 京东同步验收（账号到位后照单跑）

> 前置：P4 淘宝 / P5 京东各在「设置 → 平台账号」里用官方 WebView 登录一次；
> 登录成功后卡片必须显示「已绑定」。以下每条只报编号 + 现象。

### I1 淘宝绑定
- 点淘宝「去登录」，在官方页完成登录；返回列表显示「已绑定」。
- `bound_account` 出现 `platform=tb`，`secret` 为密文（不含 `cookie2`/`unb` 明文）。

### I2 淘宝同步
- 点「立即同步」；结果行报「新增 X · 更新 Y」或「这次没有新的到站件」。
- 首页出现淘宝来源的件：点卡片进现场模式，码/后五位、点名完整可见。
- 失败时区分：登录失效 → 账号卡红字；接口改版 → 结果 0 但不误清旧件。

### I3 淘宝轨迹字段
- `tracking_no`、`order_sn`、`carrier` 落库；轨迹里出现「取件码」时 `code_kind=PICKUP`；
  出现「出示单号后五位」时 `code_kind=SUFFIX`，现场显示「出示单号后五位」。

### I4 京东绑定
- 点京东「去登录」，在官方页完成登录；返回列表显示「已绑定」。
- `bound_account` 出现 `platform=jd`，`secret` 为密文（不含 `pt_key` 明文）。

### I5 京东同步
- 点「立即同步」；首页出现京东来源的件。
- 京东物流页 DOM 里能读出 `运单号`；拿不到运单号时这条不算过，必须记录原始轨迹片段。
- 订单状态「已签收」但没有「本人取件 / 凭码取件」时，**不许**自动标已取。

### I6 共同红线
- **已取不复活**：任一平台标已取 → 再同步 → 该件不出现在首页，`picked` 仍为 1。
- **签收不误标**：`picked` 只能由明确的本人/凭码取件触发。
- **不误清库**：同步失败、空列表、接口改版时，旧件一行都不能少。
- **检索**：搜运单号或平台订单号能命中对应卡片。

### I7 真机
- 模拟器通过不等于真机通过；真机至少复跑 I1/I2/I4/I5 + H8（v7→v8 实机升级）。

## J · 无码件入首页（需求变更：有运单号就收录）

> 判据：`stage=AT_STATION` + 非空 `pointKey` +（有码 / `SUFFIX` / 有 `trackingNo`）。
> 空码不再被过滤；无点名归「驿站未定位」。

### J1 入列（设备已验证 · MuMu Android 15）
- 淘宝同步返回 2 件 `code="", code_kind=NONE, tracking_no` 有值；
- 账号卡报「新增 2 · 更新 0」，首页出现这两件，`picked=0`。

### J2 首页卡片（设备已验证）
- 有码件仍是原样：`38-1-17031`。
- 无码件显示「暂无取件码」`Caption + InkMuted`，紧跟「待取件」`Micro`；
  **不显示任何伪造数字**，不新增状态色、不加角标、不加平台名。
- 有商品数据的账号件：行首 44dp 缩略图 + 码 + 标题单行省略 + 「店铺/价格」小字；
  行高固定 52dp，加载中/失败不改变布局；没有商品数据的行保持原样。

### J3 现场模式（设备已验证）
- `NONE` 件：不出现空白码框、不出现「长按可复制」；
  显示「这件还没有取件码」+ 运单号 + 一句淘宝用法，再一行「淘宝查询 / 复制单号」+ 灰色「查看详情」。
- 现场分三区：上区商品信息（缩略图 + 标题单行 + 店铺/价格一行）用 hairline/间隔独立；
  中区码/后五位居中、上下留白；下区提示 + 动作。
- `SUFFIX` 件：大字后五位仍是主角；码下方一句提示，然后一行收纳的次级操作
  「淘宝查询」+「复制单号」（蓝色图标 + 短词，触控高 40dp），
  「查看详情」再降一档成灰字。主区不再有黑色大按钮。
- 点「复制快递单号」→ 剪贴板是**完整运单号**（不是后五位），并出现「快递单号已复制」短提示；
- 点「去淘宝查询」→ 装了淘宝就拉起淘宝；没装时**不打开浏览器**，
  停在原屏并提示「已复制单号，去淘宝粘贴搜索」；
- `PICKUP`（真取件码）件这套入口一个都不出现，原有「长按可复制」不变；
- 静默态下这段内容仍全墨可见。

### J4 详情页（设备已验证）
- 从现场「查看详情」进入；标题「件详情」；
- 展示：完整点名、承运商 + 阶段、码/后五位或「暂无取件码」、
  同一条淘宝用法提示 +「去淘宝查询」+「复制快递单号」（`SUFFIX`/`NONE` 都有，`PICKUP` 没有）；
- 有商品数据时，元数据卡上方出现商品卡：76dp 图、标题两行、价格、店铺/下单时间；
- 元数据行：运单号 / 状态 / 取件点 / 承运商 / 订单号；下面是完整轨迹原文（可长按选择）；
- 返回键回到现场模式。

### J5 去重与已取（单测）
- 同一运单号：按运单号匹配为 `Update`，不插第二张卡；
- 空码件不会撞 `parcel_dedupe`（该索引带 `code <> ''`）；
- 无码件的不明确「已签收」：`markPicked=false`、`stage=AT_STATION`，不从待取里消失；
- 既无运单号也无码：仍 `Skip(NO_CODE)` / `Skip(NO_POINT)`。

### J6 商品信息（设备已验证 · 单测）
- 字段来源：PDD `order_list_v4` 的 goods 容器（标题/图/价/下单时间）；
  淘宝 `mainOrders[].subOrders[0].itemInfo`（标题/图/下单时间）；京东 `wareInfoList` 预留（无真实订单，未验）；
- 缺字段留 null：不伪造价格、不画空图框；图片失败显示浅灰「无图」占位，尺寸固定；
- `showsGoodsCard` 只在「账号渠道 + 有账号归属 + 至少一个商品字段」时为真；
  短信/手动/无账号归属件不显示。

### J7 空点不出现（设备已验证 · 单测）
- 首页卡片只来自 `groupByPoint`：`picked=1` 与 `picked=0` 为 0 的点都不成卡；
- 卡片数 = 有在站件的点数；某点最后一件取完，卡当场消失；
- 同步后已取件被 `ALREADY_PICKED` 跳过，不会把已空的点重新带回来。
