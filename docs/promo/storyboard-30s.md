# 32 秒产品宣传片 · 分镜脚本（无配音 / 音乐驱动）

> ⚠️ **v0.5 已按真实 BGM 重做，本篇 §1–§6 的 120 BPM / 32 秒 / 深色底版本作废**，保留作为推演记录。
> 现行版本见文末 **§11**：95 BPM / 37.9 秒 / 米白转黑。
>
> 状态：**v0.1 草案，等新素材**。B3–B6 的画面取自现有 `docs/screenshots/`；新录素材到位后重排，节拍骨架不变。
>
> 目标形态：**没有旁白**。信息全部由「真实界面 + 屏幕大字 + 音乐节奏」承担。
> 观众静音看也看得懂，开声音只是多一层情绪——这是这类片子唯一的验收标准。

## 0. 这份分镜的三个前提

**① 音乐定节拍，不是文案定节拍。**
120 BPM 工作假设：**1 拍 = 0.5s，1 小节（4 拍）= 2.0s**。全片 **16 小节 = 32s**。
所有切点落在小节线上。宁可让某个镜头"多待半秒"，也不要为了凑画面去改节奏——改了节奏，片子立刻从"作品"掉成"PPT"。

**② 画面只用仓库里已有的真实截图。**
`docs/screenshots/` 下 28 张，1080×1920。**不用 AI 生成 UI**：文字会糊，懂行的人一眼识破，而这条片子的全部说服力都在那些字和数字上。

**③ 时间码是排版预算，不是实测值。**
有配音时，镜头时长由 `gen_tts.py` 的实测时长倒推；这里没有配音，**时长由节拍表直接给定**（见 §6 的渲染改动）。

## 2. 逐镜脚本

### B1 · 00:00–00:04 ·「三个地方」

- **素材**：无。纯色底 `#0C0C0D`，无渐变、无噪点。
- **画面**：三行字左对齐，x=120（竖版 x=96），垂直居中偏上。逐行出现：0.0s／1.2s／2.4s，每行 0.28s 上移 24px + 淡入，停留到 3.6s 整体淡出。
- **文案**：
  ```
  取件码在三个 App 里。
  快递在三个柜子里。
  你站在中间。
  ```
- **为什么这么写**：前两句是事实（观众点头），第三句把镜头从"货"转到"人"。第三句只有五个字，留白最多，正好是音乐 drop 前的最后一拍。
- **反复确认过的点**：这三句不是产品主张，是**场景**。主张留到 B8，收尾才有落地感。

### B2 · 00:04–00:06 · 产品登场

- **素材**：`docs/screenshots/00-onboarding.png`
- **画面**：卡片从下方 120px 推入（0.45s，缓出），落定在画面中偏右；卡片本身完整、圆角、带投影，**不裁切**。
- **文案**：主行「卡皮巴拉快递助手」（随卡片一起进），副行「取快递，看一眼就行」延后 0.3s 从主行下方浮出。
- **卡点**：卡片落定必须踩在 4.0s 的 drop 上。这是全片唯一一次"声音和画面同时砸下来"，只能用一次。
- **注意**：这张截图里有「先看演示」按钮和「无需注册·无广告·开源·数据只在本机」——**都留着**。B7 会正面讲这三件事，这里先让它们当背景证据。

### B3 · 00:06–00:10 · 按取件点分好

- **素材**：`docs/screenshots/01-home-samples.png`
- **画面**：整屏卡片，镜头从顶部缓慢下移 6%（不缩放，只平移），保证「丰巢 2 件」和「菜鸟 3 件」两张卡同时在框内。
- **动效**：8.0s 时，丰巢卡片左侧那条红色状态条做一次 0.35s 的亮度脉冲（透明度 100%→55%→100%），同时右侧「2 件」轻微放大 4%。
- **文案**：主行「按取件点分好」，副行「最急的那件，排在最上面」。
- **为什么用平移不用推近**：这一屏信息密度最高，推近会裁掉第三张卡，观众会以为下面没了。平移能暗示"还有"。

### B4 · 00:10–00:14 · 现场模式

- **素材**：`docs/screenshots/02-onsite-demo.png`
- **画面**：从整屏缓推到「8-3-1024」占画面宽度 78%，推近终点 13.2s，末段 0.8s 停稳（不给任何抖动余地）。
- **动效**：13.2s 时数字做一次 ±1.5% 的 scale 呼吸，踩在拍点上；下方「格口 A12」这一块不动——它是参照物，动了观众会失焦。
- **文案**：主行两行「站到柜前」／「一眼就是码」，副行「超时了，先替你算钱」。
- **必须保留**：红色那行「已超时 · 0.5 元/12 小时（上限 3 元）」。它是这一屏的价值所在，也是"我们敢把丑话说在前面"的证据。副行就是给这行字配的画外音。

### B5 · 00:14–00:20 · 三种码写法

三个镜头，**每个 1 小节（2.0s）**，切点 14.0 / 16.0 / 18.0。

| 时间 | 素材 | 取景 | 屏幕文字 |
|---|---|---|---|
| 14.0–16.0 | `demo-feedback.png` | **局部特写**：只保留「5-2-3391」+「货架 3排12号」 | 格子号 |
| 16.0–18.0 | `demo-suffix.png` | **同构特写**：只保留「76416」+「后五位」 | 货架号 |
| 18.0–20.0 | `demo-none.png` | **同构特写**：只保留「这件还没有取件码」 | 后五位 › 没有码 |

- **为什么用局部特写而不是整屏**：三张截图状态栏时间是 17:45／?／18:50，快速三连切时右上角的钟会跳，观众会察觉"这是拼的"。统一裁到码区，三个画面**视觉同构**，观众读到的才是"写法不一样"，而不是"三个不同页面"。
- **文案**：主行居中压在三连切上方，**全程不换**：「格子号 · 货架号 · 后五位」。副行在 18.5s 才出现，位置从主行下方淡入：「认不出来，就说认不出来」。
- **音效**：每次切镜一个极短的 click（-18 dB，8ms 内衰减）。第三个 click 略低半音——它在说"这次不对"，和副行配合。

### B6 · 00:20–00:24 · 取完就走

两镜，各 1 小节。

| 时间 | 素材 | 画面 | 屏幕文字 |
|---|---|---|---|
| 20.0–22.0 | `demo-point-done.png` | 整屏，缓推 3% | 取完这件 |
| 22.0–24.0 | `demo-all-done.png` | 整屏，从下方推入 | 下一件已经在等你 |

- **文案排布**：20.0s「取完这件」→ 21.4s 追加「，下一件已经在等你」跨镜连读。字不断，画面在 22.0s 换。**声音和字不切在一起，画面切在字中间**——这是无配音片最省力的"高级感"来源，因为观众的眼睛在追字，画面换了他会以为是自己漏看了。
- **必须保留**：「🎉 本月共取 6 件」。这是全片唯一的"正面数字"，其余镜头都在讲麻烦。

### B7 · 00:24–00:28 · 三行信任

- **素材**：无 UI，纯色底 `#0C0C0D`。
- **画面**：三行依次出现，间隔 1.0s（24.0／25.0／26.0），字号逐行递增（56→64→76px），最后一行停留到 27.4s。
- **文案**：
  ```
  离线解析
  不注册，不联网
  数据只在这台手机上
  ```
- **卡点**：24.0s 鼓**全部停掉**，只留一层低频 pad。B6 的鼓点刚收完就断，这一断是全片情绪最低点，也是 B8 落地的起跳板。
- **为什么这里必须静**：前 24 秒一直在给信息，这一段要让观众"喘"。观众喘气的这三秒，正好读完三行字。

### B8 · 00:28–00:32 · 品牌收尾

- **素材**：`fastlane/metadata/android/zh-CN/images/icon.png`（512×512 图标，矢量重绘过，边缘比截图里的头像干净）
- **画面**：28.0s 图标从 92% 缩放到 100%（0.5s，缓出）；28.5s 产品名；29.5s tagline；30.5s 底部小字；32.0s 淡出到黑。
- **文案**：
  ```
  卡皮巴拉快递助手
  取快递，看一眼就行
  ——— GitHub · GPL-3.0 · 无广告 ———
  ```
- **注意**：tagline 和 B2 的副行是同一句。**这是故意的**：开场用它介绍，收尾用它盖章。中间 24 秒讲的全是证据，最后回到那句承诺上。

## 3. 版式规范（横竖两版）

### 竖版 1080×1920

| 元素 | 规格 |
|---|---|
| 底色 | `#0C0C0D` |
| 界面卡片 | 宽 880（左右各留 100），圆角 28，投影 `0 24 60 rgba(0,0,0,.18)` |
| 主文案 | 88px（基准）/ 思源黑体 Bold / 行高 1.25 / 左对齐 x=100 |
| 副文案 | 40px / Medium / `#A8A29E` |
| 文案区 | 卡片下方独立区域，高度 ≥ 240。**永不叠在卡片上** |

### 横版 1920×1080

| 元素 | 规格 |
|---|---|
| 界面卡片 | 高 920（宽 517），置于右侧 x=1300 区域居中，y=80 |
| 文案区 | x=120–1180，左对齐，垂直居中 |
| 主文案 | 72px / 行高 1.3 |
| 副文案 | 36px |

### 两版共同的三条铁律

1. **任何一帧都不裁切界面**。卡片四边永远完整，运镜放大时四周留 ≥ 80px 安全边距。
2. **文字永远不压在卡片上**。横版文字在左、卡片在右；竖版文字在下、卡片在上。字幕条叠底的方案不采用——它一定会压住某一行码。
3. **背景不用渐变、不用光斑**。深色纯底 + 真实界面，让眼睛只落在码上。

## 4. 音乐与音效

| 项 | 要求 |
|---|---|
| BPM | 120（1 小节 = 2.0s），不接受变速 |
| 结构 | 需要一个明确的 drop（给 B2）、一次 breakdown（给 B7） |
| 人声 | **无 vocal**。有人声就会跟屏幕文字抢注意力 |
| 来源 | Pixabay Music / Free Music Archive（CC0 或 CC-BY）/ Uppbeat。**别用可能触发 Content ID 的曲目**——这条片子会发到 B 站和视频号 |
| 响度 | -14 LUFS 整体，真峰值 ≤ -1 dBTP（各平台统一） |
| 音效 | 三声 click（B5）、一声轻 chime（22.0s 全取完）、B1 一个低频 pulse |

**选曲的硬标准**：前 4 秒必须有"没鼓但有东西在动"的段落。B1 是纯文字镜，配一个从头就在砸鼓的曲子，那三行字会被节奏推着读完，观众来不及理解"你站在中间"。

### 关于水豚

B1、B7、B8 三处是纯色底 + 文字，**没有任何形象**。加一张水豚的关键视觉会让片子立刻有主人。可选路线：
- 用内置图像生成做一张水豚站在快递柜前的插画（单张约 5–10 积分）；
- 或者干脆不加——**极简片不加插画也成立**，只是会少一点记忆点。

两种都行，但别做"AI 生成的水豚动起来"那种 3 秒片头：动起来的假水豚会把一部克制的产品片拽成广告。

## 6. 渲染器要改的三处

现成脚本是**按配音时长驱动**的，无配音版得动三处（都在 `promo-video-maker/scripts/`）：

| 位置 | 现状 | 改成 |
|---|---|---|
| `render_video.py` `build()` 293–296 行 | 找不到 `s{k}.mp3` 直接 return None；时长 = 配音时长 + PAD | 时长从节拍表读（`SCENES[k]['dur']`），`audio=None` |
| `video_config.py` `SCENES` 的 mode | 只有 `book` / `card` / `close` | 加一个 `type`（纯文字镜，B1 和 B7 用） |
| `build()` 末尾 concat 之后 | 每段自己带音轨 | 各段**渲成静音**，concat 完再用 ffmpeg 铺一条 BGM：`-filter_complex "[1:a]afade=in:st=0:d=0.8,afade=out:st=30:d=2[a]"` |

`render_scene()` 已经接受 `audio=None`（`close` 镜就是这么调的），所以改动量很小，不需要重写渲染核心——**防抖那套（2x 超采样 + 浮点 box）原样保留**，那正是这条片子最值钱的部分。

## 9. 素材实测（2026-11-15 录屏，v0.2 依据）

五段录屏实测结果，比原计划多出两条硬约束：

| # | 时长 | 内容 | 处理 |
|---|---|---|---|
| 1 | 5.2s | 设置页切深色模式 | 可用（需裁状态栏） |
| 2 | 11.1s | 淘宝身份码（真码 + 账号手机号 + 红包广告浮层） | **不用** |
| 3 | 4.9s | 拼多多身份码（真码） | **不用** |
| 4 | 18.1s | 主流程，全程标「这是演示数据」 | **主力素材** |
| 5 | 8.0s | 门禁码 8809 1122 + 会员码 CN 8890 2211（App 自标「演示用码」） | 可用，替代身份码镜 |

**约束一：静止窗口只有 0.85–0.95 秒。**
用 `freezedetect` 扫第 4 段，界面真正停住的窗口是 0.29–1.14 / 2.55–3.51 / 3.85–4.73 / 12.60–13.48 秒，**没有一段超过 1 秒**。
后果：**"缓推 3.6 秒"不可能靠播放录屏实现**——推近必须对静止帧做（拉伸播放率 = 0.23，或直接取单帧做镜头运动）。
录屏的真正价值是**手势与转场**（点击、跳转、页面切换），那是静态截图给不了的。原分镜里"整屏缓推"的写法改成：静止段做推近，动作段原速播放。

**约束二：状态栏必须统一裁掉 100px（1600 的 6.25%）。**
时间有 11:40 / 11:43 两种，且挂着五个通知图标（B站、微信、淘宝、小红书、美团）。裁完顶部正好是「待取件 / 演示模式 · 示例数据」，无残留。输出比例因此从 9:16 变成 720×1500（0.48），版式按这个比例算。

**约束三：720×1600 升到 1080×1920 是 1.5 倍放大。**
大数字没问题，小字会略软。要更锐，下一轮在开发者选项里把录制分辨率调到 1080×2400。

**技术验证片的取段**：第 4 段 3.90–4.72 秒（8-3-1024 / 格口 A12 / 已超时 0.5 元），25 帧，拉伸 4.3 倍到 3.6 秒。

### 仍然开着的

- **无音轨**。粗剪只验结构，节奏感要等 BGM 到位才判得准。
- **B4 特写**（11.6–14.0s）是故意让卡片溢出画幅的，读作"推进去"；这条破了 §3 的"永不裁切"规则，是唯一一处例外，已确认码本身完整可见。
- B6 第二镜「都取完了」那张静帧内容集中在卡片上部，下半是空渐变——真实界面就是这样，精修时可考虑把卡片再往下压 40px 平衡构图。

### 待定的"炫酷"增量（按风险从低到高）

1. 卡片入场换成遮罩擦除（mask wipe），替代现在的上浮——零风险，观感提升明显。
2. B7 三行改逐字出现——低风险，但中文字距会跳，需要逐字定位。
3. 码从模糊到清晰（0.3s），配一声 click——低风险，正好卡在鼓点上。
4. 片头 2–3 秒字/图形爆发段——高风险，也是唯一需要另外调参的部分。

### v0.4 追加：B5.5 门禁码一镜

加它的理由：全片其余六镜都是「静帧 + 缓推」，只有 B4 特写有节奏变化。B5.5 是唯一一个**码本身在变**的镜头（从糊到清），而且它承载了 README 里那句「二维码在手机上现算」——这一条是别的取件 App 做不到的，值得单独给两秒。

素材用第 5 段的门禁码（`8809 1122`），App 自己在画面上标着「演示用码，不是任何真实门禁」，**不需要打码**。

**踩到的两个坑，记下来省下一次：**

1. `filter: blur()` 是生效的，但**采样点选错会误判成没生效**——0.4 秒的对焦过程，第 600 帧糊、608 帧已全清晰。另外 `ffmpeg -vf select='eq(n,600)'` 有帧号偏移，按帧精确取要用 `trim=start_frame=600:end_frame=601`。
2. **并发 4 时 Edge 会偶发起不来**（`BrowserRunner` 报错），并发降到 2 就稳定。全片渲染约 100–140 秒，不值得为那点速度冒险。

### 11.1 音乐实测

| 项 | 实测 | 说明 |

### 11.2 四支参考片给出的三条结论

1. **切点密度不是关键**。四支的切点密度 0.16–0.36 刀/秒，比多数人想象慢。酷来自**持续运动**，不是快切。
2. **大字要当主角**。ref3/ref4 整镜只有字。上一版每镜都是"卡片+小标题"，字永远在打工。
3. **界面要是活的**。ref1 用 Google 搜索框的 `Generating...` 骨架加载讲产品，上一版用静帧推近，界面是死的——这是上一版最大的判断失误。

### 11.4 "白变黑"的动机
