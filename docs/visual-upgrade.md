# 视觉升级方案（v0.4）

> 依据：[多邻国录屏逐帧拆解](duolingo-teardown.md)、[文字层级规则](text-hierarchy.md)、
> 现有 `Palette.kt` / `TypeScale.kt` / `MotionTokens.kt` 与 `tools/visual-audit.py` 的棘轮。
>
> 这份文档只写**要改什么、改成什么、怎么验**。不写「应该更现代」这类形容词。

---

## 0. 一句话诊断

我们的界面现在**信息是对的、密度是合理的、层级也收敛过了**，缺的是三样：

1. **状态没有形状**：所有卡片都是「白底 + 1dp 描边」，待取/临期/已取/失效只能靠一条 10dp 色条和一个角标区分。
2. **动效只覆盖了「换屏」**：进屏有动效，但「在动的东西」（同步、取件、刷新）几乎都是静态的。
3. **按钮没有厚度**：全部是平色块，按下去只缩 0.97，缺少「按到实体」的那一下。

多邻国的录屏证明这三件事的收益远超换配色：它的高级感来自**同一屏只有两样东西在动**、
**按钮有 3dp 键程**、**状态用填充+描边而不是色条**。

## 1. 目标（可验收）

| 编号 | 目标 | 验收方式 |
|---|---|---|
| G1 | 卡片状态可以用「填充 + 描边」读出，不依赖色条 | 遮住颜色只看灰度，仍能分出待取/临期/已取/失效 |
| G2 | 任何一个「正在发生的事」都有可见的运动 | 同步、刷新、取件三处都能看到进度或位移 |
| G3 | 所有主按钮有键程 | 按下时下沉 ≥3dp，松手回弹 |
| G4 | 不引入新字体、新色板 | `visual-audit.py --ci` 的棘轮只许更好，不许放宽 |
| G5 | 暗色档同等成立 | 亮/暗两套截图逐项对照 |

## 2. 三条主线

### 2.1 卡片四态（G1）

**现状**：`PointCard` 用 `SurfaceCard` + `Hairline` + 左侧 10×40dp 色条 + 文字标签。
26 处 `border(1.dp, Hairline)`、32 处 `background(SurfaceCard)`，几乎全是同一个形状。

**目标**：借多邻国的「未选 / 已选 / 正确 / 失效」，映射成我们真实的四态：

| 我们的状态 | 语义 | 填充 | 描边 | 文字 |
|---|---|---|---|---|
| 待取（安全） | 还没到期 | `SurfaceCard` | 1dp `Hairline` | `Ink` |
| 临期 | 快到点了 | `UrgencyDueSoonTint` | 1.5dp `BorderDueSoon` | `Ink` |
| 已取（刚取） | 刚完成 | `UrgencySafeTint` | 1.5dp `UrgencySafe.copy(alpha=.45)` | `Ink` |
| 已退休 / 已忽略 | 不再关心 | `SurfaceSunken` | 1dp `Hairline` | `InkMuted` |

**关键取舍**：**保留色条**。多邻国的块没有色条是因为它只有四种状态；我们的卡片同时要表达
「哪个点」和「多急」，色条是首页唯一的颜色编码位置，删掉会让紧急度更难扫。
改的是**底色和描边**，让状态在余光里就能看出，而不是必须先读那条色条。

**落地**：新增 `ui/CardState.kt`，一个 `Modifier.cardState(state)`：

```kotlin
enum class CardState { IDLE, URGENT, JUST_DONE, RETIRED }

fun Modifier.cardState(state: CardState, shape: Shape = ShowCodeShapes.Md): Modifier
```

消费点（按优先级）：`PointCard`、`InTransitSection`、`SyncRailPanel`、`UnrecognizedRow`、`SettingsNavRow`。

### 2.2 运动：让「在动」可见（G2）

多邻国的证据：进度条答对时**过冲 5% 再回落，0.46 秒**；反馈带**上升 0.44 秒**。
两段都是弹簧，不是线性。

我们已有的 token（`MotionTokens` / `MotionProfile`）：

| token | 参数 | 现用途 | 计划用途 |
|---|---|---|---|
| `MotionProfile.iconSpring()` | 0.68 / 420 | 图标、按压 | 取件成功带、勾的落位 |
| `MotionProfile.pageSpring()` | 0.74 / 180 | 换屏 | 换件 |
| `MotionTokens.NavSettle` | 0.60 / 310 | 底栏指示器 | **同步通道的进度填充** |
| `MotionTokens.LiquidSettle` | 0.80 / 420 | 胶囊 | 进度条到位 |

**三处要加的运动**：

1. **同步通道进度**：`RUNNING` 状态现在只有一个转动的弧。改成：
   - 通道行右侧一条 2dp 宽、48dp 长的细进度，按 `SyncProgress.done/total` 填充；
   - 填充用 `NavSettle`（有过冲），不用 tween；
   - 每完成一件，进度条推进一步 + 一次 `HapticFeedbackType.TextHandleMove`。
2. **刷新键**：现在转 560ms 的圈。加一条**顶部 2dp 的进度条**（在轨道下面），
   同步期间按通道数推进；结束淡出 120ms。
3. **取件换件**：`HorizontalPager` 已有 0.97/0.22 的邻页露边，但切换本身没有「到位感」。
   给当前页加一个 `pageSpring` 的轻微 y 位移（+6dp → 0），让「换了一张」有落点。

**不做**：整屏缩放、背景视差、逐字打字机。多邻国一处都没用，我们的场景更不该用。

### 2.3 按钮键程（G3）

多邻国的实测：主按钮 328×49dp，圆角 12dp，**底部 3dp 的 `#50AE00`**，按下时整颗键下沉。

**我们已有的实现**（上一轮）：`PickedButton` 加了 4dp 底边 + 下沉 3dp。现在把它抽成通用组件：

```kotlin
// ui/SolidButton.kt
@Composable
fun SolidButton(
    text: String,
    onClick: () -> Unit,
    tone: ButtonTone = ButtonTone.Ink,   // Ink / Safe / Accent
    enabled: Boolean = true,
    modifier: Modifier = Modifier,
)
```

- 底边色 = 主色压暗 18%（`Ink` → `Ink.copy(alpha…)` 不行，要真的算一个深色）；
- 按下 `translationY = 3.dp`，松手回弹 `MotionTokens.NavRelease`；
- 按下时 `HapticFeedbackType.ContextClick`。

**消费点**：现场「已取」、引导「绑定平台账号」、规则页「保存」、手动导入「保存」、身份码「存一张」。
这 6 颗是产品里唯一的「主行动」，其余保持文字按钮。

## 2.4 已落地的动效（本轮）

`ui/motion/MotionKit.kt` + 四处接线。三条原则写在文件头：只在有信息时动、弹簧优先、
减少动画时全部退化。

| 动效 | 位置 | 参数 | 说什么 |
|---|---|---|---|
| `pressLift` | 首页取件卡 | 上浮 2dp / 放大 1.2% / 阴影 6dp，`NavRelease` | 「这张卡被拎起来了」 |
| `DrawingCheck` | 成功带的勾 | 路径 180ms 描出，先短边后长边 | 「完成了」被看见的时间 |
| `ScanSweep` | 首页列表 | 900ms，22% 屏高柔光 + 1dp 前沿线 | 「正在一页一页看过去」 |
| `BreathingRing` | 同步通道 | 1.4s 周期，alpha 0.18↔0.60 | 「有人在干活」，不是卡住 |
| 落点 | 现场换件 | 未落定时下移 8dp，随 `pageOffset` 归零 | 「换了一张」有物理落点 |
| 对焦 | 现场取件码 | 0.94→1.0 + 上移 6dp，`iconSpring`（≤180ms） | 镜头对焦；减少动画时直接落终态 |
| 收束脉冲 | 轨道四通道 | 1 → 1.45 → 1，90ms 上冲 + `NavRelease` 回落 | 「都回来了」 |

**对焦那条的红线**：动画必须在 180ms 内结束，且结束时码必须完全清晰。
任何可能让扫码机在动画途中看到模糊码的时长都不可接受——这是它唯一不能被「做得更好看」覆盖的约束。

### 2.5 「已取」键：淡灰 → 绿（多邻国那颗继续键）

三段，实测值：

| 段 | 时长 | 颜色 |
|---|---|---|
| 静止 | — | 面 `ActionRest`（亮 `#E8ECF3` / 暗 `#39434F`）+ 1dp 描边 + `InkSecondary` 文字；**文案「拿走了」** |
| 转绿 | **110ms** | 面 → `#00B578`（`UrgencySafe`），底边 → `#00A16B`（`UrgencySafeEdge`），文字 → 白；**文案「已拿走」** |
| 停留 | **220ms** | 保持绿 |
| 退灰 | 200ms | 回到淡灰，此时下一件已经换上来 |

**为什么静止是淡灰而不是黑**：黑按钮读作「危险/最终确认」，而这颗键是这一屏唯一要按的东西。
淡灰 + 描边读作「等着被按」，按下转绿才是「做成了」。

**为什么暗色要单独一档底色**：暗色画布是 `#0F1218`，`SurfaceSunken` 是 `#252B35`——只差一档，
那颗键会沉进背景里、读不出「这里有个东西可以按」。所以新增 `ActionRest`（暗色 `#39434F`）
和 `ActionEdge`（暗色 `#272E38`，比面**更深**，因为暗色下键程不能靠「更亮」表达）。
亮色档两者分别是 `#E8ECF3` / `#D5DCE7`，与原来一致。

**为什么文案不是「已取」**：淡灰底上的「已取」会被读成「已经取过了」——一颗看起来已完成的键，
用户不会去按。所以静止写动作（**拿走了**），变绿的那 220ms 才写结果（**已拿走**）。
这是这颗键唯一会骗人的地方，靠颜色 + 文案两处一起堵。

**红线**：`onClick` 在**第一帧**就发出去（loading-submit 不允许状态等动画），绿只是这一颗键自己的表演。
`firing` 期间二次点击被吞掉，避免连点连跳。

### 2.6 手感档（按阻尼比反算，不是凭感觉）

上面几节的弹簧参数原来是从教务搬来的（`iconSpring` 330ms、`NavRelease` 492ms），
它们解决的是「有没有动效」；这一组解决「动得对不对」。每一档都先算过冲与稳定时间再定：

| 档 | 阻尼 / 刚度 | 过冲 | 稳定 | 用在哪 | 为什么 |
|---|---|---|---|---|---|
| `PressDown` | 0.85 / 1000 | 0.6% | **171ms** | 按键沉入、缩 0.98 | 超过 200ms 就跟不上手指 |
| `PressLift` | 0.70 / 650 | 4.6% | **258ms** | 抬起、回弹 | 2% 像 tween，8% 像玩具 |
| `Focus` | 0.92 / 1800 | 0.1% | **118ms** | 现场码对焦 | 扫码机可能中途取帧，不能还在弹 |
| `Land` | 0.80 / 550 | 1.5% | **245ms** | 换件、面板归位 | 位置移动过冲会读成没对齐 |
| `Settle` | 0.62 / 700 | 8.4% | **281ms** | 收束脉冲 | 唯一允许明显弹一下的地方 |

按下与抬起**用两条不同的弹簧**：同一条管两个方向，按下会比手指慢半拍。

### 2.7 亮暗开关（照 Figma 参考图 1:1 量）

不是 Material 的 `Switch`（那是拨杆），是「嵌进卡片里的凹槽 + 槽里一颗小球」。
全部尺寸按参考图比例换算（以轨道高为 1）：

| 元素 | 参考图 | 比例 | 实现 |
|---|---|---|---|
| 轨道宽 | 212px | 2.16 | 95dp |
| 轨道高 | 98px | 1 | 44dp |
| 凹槽（天空）高 | 86px | 0.88 | 36dp |
| 球直径 | 68px | 0.69 | 28dp |
| 球到槽壁 | 9px | 0.09 | 2.5dp |

**关键一条：球比槽小、完全嵌在槽里。** 球一旦溢出轨道，就从「嵌进去的圆钮」退化成
「滑块」——那是第一版做错的地方，用户当时说「太阳月亮都太大了，超出了框框」。

三处刻意做减法（都是第一版做错、被指出来才改掉的）：

| 第一版 | 问题 | 现在 |
|---|---|---|
| 太阳画了 8 条光芒 | 像齿轮 | **纯色实心圆**，参考图里本来就没有光芒 |
| 太阳加了中心高光 | 深色槽上渲染成一道可见的环，像塑料盖 | 什么都不加 |
| 球下缘画了暗弧 | 渲染成一道月牙，是「丑」的直接来源 | 删掉，只留落影 |
| 槽底画了亮线 | 横穿球下方，像一道白划痕 | 删掉 |

**主题管道**（这才是真活）：`ThemeController` 是进程级单例，改 `mode` 立刻换
`ShowCodePaletteState` 快照，全 App 重组——**不重建 Activity**，所以那颗开关的
滑动动画能完整播完。落盘在 `Prefs.themeMode`，冷启动时在 `setContent` 之前装好，
避免暗色首帧先画一遍亮色。

## 4. 不做清单（明确写下，避免以后反复讨论）

| 不做 | 原因 |
|---|---|
| 连击 / XP / 排行榜 | 取件工具一周用几次，做每日打卡是骚扰 |
| 音效 | 柜机前、办公室，默认出声是冒犯 |
| 暗场 + 上滑仪式 | 手上可能要拿包裹，多一步手势就是多一次失败 |
| 吉祥物情绪施压（哭泣/催促） | 只在「做完了」时出现，不做负面情绪 |
| 每件都撒纸屑 | 连续取三件会挡手，奖励只在最后一件 |
| 新字体 | 现有字阶已收敛，换字体要重跑全部视觉棘轮 |

## 8. 开放问题（需要拍板）

1. **色条去留**：本方案保留。若你希望更接近多邻国的纯块状，删色条后紧急度只能靠描边颜色——
   在 3 米外（现场场景）会变弱。
2. **同步进度条的位置**：放在轨道下沿（整条一条）还是每个通道行内（每行一条）？
   本方案选后者，因为能直接指出「是哪一家在推进」。
3. **`SolidButton` 是否替换引导页的大选择卡**：引导页现在两张卡（深/浅），
   加键程会更像多邻国，但会让「选择」变成「按钮」，语义略微变窄。本方案**不动引导页**。
